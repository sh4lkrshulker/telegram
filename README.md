# Линия

Небольшой мессенджер с поиском по имени пользователя и личными сообщениями. Интерфейс размещается как статический сайт на GitHub Pages, а аккаунты и переписки хранятся в Supabase.

## Настройка Supabase

1. В Supabase открой **Authentication → Providers → Email** и включи регистрацию по email и паролю. Можно оставить **Confirm email** включённым: приложение отправит письмо и создаст профиль после подтверждения.
2. Открой **SQL Editor**, вставь содержимое `database.sql` и запусти запрос. Скрипт создаёт схему профилей, личных сообщений, кошельков, подарков и групп/каналов, а также включает RLS и необходимые RPC-функции.
3. В **Project Settings → API** возьми **Project URL** и **Publishable key** (или старый `anon` key). В `app.js` уже указаны URL и ключ этого проекта. Это статическая страница для GitHub Pages, поэтому переменные `NEXT_PUBLIC_...` сами не подставятся. В браузерный код нельзя добавлять `service_role` key.
4. SQL включает таблицы личных и групповых сообщений в `supabase_realtime`, если публикация доступна.
5. В **Authentication → URL Configuration** добавь URL опубликованного GitHub Pages сайта в **Redirect URLs**, чтобы ссылка подтверждения возвращала пользователя в приложение.

Проект настроен на URL `https://ilcxearxoovnlhowhjzl.supabase.co`. Убедись, что SQL выполнен именно в этом проекте.

## Запуск и публикация

Для локального запуска открой `index.html` через Live Server в VS Code. Для GitHub Pages загрузи файлы этой папки в репозиторий, затем выбери **Settings → Pages → Deploy from a branch**, ветку `main` и папку `/ (root)`. После публикации сайт подключается к Supabase напрямую из браузера.

## Как войти

При регистрации пользователь указывает email, пароль длиной не менее 8 символов и уникальный юзернейм из латинских букв, цифр и `_`. Для входа используются email и пароль; другие пользователи находят аккаунт по юзернейму. Аккаунт хранится в Supabase Auth, профиль — в `chat_profiles`.

Имена доступны для поиска вошедшим пользователям. В настройках можно изменить отображаемое имя, описание и эмодзи аватара. В личном чате доступны визуальные подарки, которые списывают очки отправителя и начисляют их получателю; это внутриигровые предметы, блокчейн/NFT не подключён. Группы и каналы поддерживают публичный поиск, вступление, приглашения и права участников.

## Администрирование и очки

В панели настроек есть вход по коду `admin123`; после входа можно просматривать пользователей и выдавать очки. Это общий код, заданный в `database.sql`, а не персональная учётная запись администратора: любой пользователь, знающий код, может открыть панель и выдать очки. Для публичного сервиса замени его в функциях `admin_list_chat_users` и `admin_grant_chat_points` на собственный секрет до запуска SQL. Не используй один общий код как единственную защиту для ценных или денежных активов.

Баланс и подарки обрабатываются функциями базы данных, а не доверяют значениям из браузера. RLS не позволяет клиенту напрямую менять баланс очков или журнал начислений.
